# Reevo design-repo

A machine-readable design system for the Reevo marketing site clone: tokens, primitive/component/section contracts, page templates, a route table, a compatibility (rhythm) graph, a PageSpec JSON Schema and a semantic validator. It lets a generator assemble a new page as a validated PageSpec from a closed set of parts instead of free-form markup.

Status: `design-review-pending`, `productionApproved: false` (see `registry.manifest.json`).

## Licensing and use

The source is a real, live company's site (Reevo). This repository is for local/internal use only. Never publish it. Generators must never reproduce real logos, real people's photos or real proprietary content; the binding list is `globalProhibitions` in `assets/asset-roles.json`. The zip (`design-repo.zip`) is a build artifact generated fresh, last, after verification passes: never commit it (it is in `.gitignore`).

## Layout

```
registry.manifest.json     entry points, counts, versions, status
tokens/
  00-foundation/           raw values (color, typography, spacing, radius, elevation, motion, breakpoint, icon-size)
  10-semantic/             semantic roles that reference foundation tokens
  20-component/            per-component values (button, nav, marquee, pattern-strip, tag-chip)
  30-layout/               container, grid, section rhythm
  themes/                  light.json, dark.json (semantic tokens resolved per theme)
  llm/                     token-catalog.json, token-policy.json, component-allowlist.json
primitives/  components/  sections/     one JSON contract per id (props, variants, content.fields, motion, responsive)
templates/                 templates.json, routes.json, verify_routes.py
compatibility/             graph.json (rules), verify_rules.py
assets/asset-roles.json    closed asset-role registry, pinned roles, global prohibitions
schema/                    pagespec.schema.json (generated), example.pagespec.json, semantic_validate.py, tests/
extraction/                build_schema.py, verify_all.py, prove_drift.py, measured-values.json
```

## Verify

```
python3 extraction/verify_all.py          # every check; exit 1 on any FAIL
python3 extraction/prove_drift.py         # injects each defect into a scratch copy; proves the check catches it
python3 schema/tests/adversarial_test.py  # mutated PageSpecs must be rejected; the control must pass
python3 extraction/build_schema.py        # regenerate schema/pagespec.schema.json (never hand-edit the schema)
python3 extraction/verify_all.py --citation-selftest
```

Requires Python 3 and `jsonschema`. The scripts derive the repo root from their own location. Checks that need the source project (citation ranges, `verify_routes.py`, which reads `../src/App.jsx`) degrade to WARN when no sibling source tree exists; they are not skipped silently.

## How a generator should use this repo

1. Read `registry.manifest.json`, then `tokens/llm/component-allowlist.json`: the closed list of ids and each section's `settableProps`. Use nothing outside it.
2. Pick a route and its template from `templates/routes.json` and `templates/templates.json`; the template fixes the required and optional section sequence.
3. For every section node read its contract in `sections/` (content fields, `maxWords`, variants, motion, responsive) and fill `content` exactly; every motion block needs a `reducedMotionFallback`.
4. Use only tokens listed in `tokens/llm/token-catalog.json` under the rules in `token-policy.json`; never invent raw values.
5. Media fields take an `assetRole` from the closed enum; obey each role's `generationPolicy` and the global prohibitions.
6. Emit a PageSpec (see `schema/example.pagespec.json`), then run `python3 schema/semantic_validate.py <spec.json>`. Schema-valid is necessary, not sufficient: the semantic validator checks template cross-reference, graph rules, asset roles and word budgets.

## Deliberate deviations from the original and known gaps

- Compare tables use `overflow-x-clip` at 390px viewport width, a deliberate deviation.
- The product-tour dialog exit is assumed, not observed.
- In-view thresholds such as 0.3 are guesses.
- The source code has no `prefers-reduced-motion` handling, so every `reducedMotionFallback` in the contracts is a proposal, not observed behavior.
- Blog bodies are lorem-ipsum placeholders and release notes are rewritten, not the originals.
- Forms never submit.
- `/thank-you` and `/product-tour/post-interactive-demo` are unbuilt.
- `/privacy` and `/terms` link out to reevo.ai and have no template.
- The `*` catch-all renders Home.
- `retrievalEligible` in `templates/routes.json` is a local definition, not an external standard.
- `condition` and `nestedIn` in `templates/templates.json` are not machine-enforced.
- Contract `constraints` beyond onePerPage / maxPerPage are not enforced by the validator.
- The `maxWords` budgets are derived from observed copy, not from any published limit.
- Only `allowlistVersion` is machine-checked; `repositoryVersion` and `pageSpecVersion` are documentation-only.
- This is a snapshot of the source project at 2026-09-30; it does not track later changes to it.
